# RFM 세그먼테이션 방법론

[03 RFM 노트북](../notebooks/03_rfm_segmentation.ipynb)의 점수화와 해석 기준이다.
금액·재방문·코호트 정의는 [분석 지표 계약](metric_contract.md)을 우선한다.

## 1. 지표

기준일은 `2019-12-31`이다.

| 지표 | 정의 |
|---|---|
| Recency | 기준일 − 마지막 구매일 |
| Frequency | 고유 거래ID 수 |
| Monetary | 할인 후·GST 포함·배송비 제외 상품 매출 합계 |

## 2. 1~5점 변환

- R: Recency 5분위, 최근일수록 고점
- F/M: Q1, Q2, Q3, `Q3 + 1.5×IQR` 경계
- F/M 5점은 상위 이상치 구간이며 R의 분위 점수와 분포가 대칭적이지 않다.

## 3. PCA 분산 가중치

R/F/M 점수를 RobustScaler로 변환한 후 PC1 절대 로딩을 합이 1이 되도록 정규화한다.

| 지표 | 가중치(2019 실행값) |
|---|---:|
| R | 약 0.20 |
| F | 약 0.34 |
| M | 약 0.46 |

```text
RFM Score = (R×wR + F×wF + M×wM) / 5 × 100
```

PC1 로딩은 고객 간 분산을 압축하는 방향이다. Monetary가 미래 매출이나 재방문에 가장
중요하다는 뜻이 아니며 인과적·예측적 중요도로 설명하지 않는다.

## 4. CRM 등급 컷

| 등급 | 점수 |
|---|---:|
| Diamond | 95 이상 |
| Platinum | 80 이상 95 미만 |
| Gold | 65 이상 80 미만 |
| Silver | 50 이상 65 미만 |
| Bronze | 50 미만 |

점수 컷은 설명 가능한 운영 규칙이다. 다만 R/F/M 경계와 PCA 가중치를 데이터마다 다시
학습하므로 컷 숫자만 고정해도 등급 안정성이 보장되지는 않는다.

운영 적용 시 다음을 함께 버전화한다.

1. 학습 기준 기간과 기준일
2. R/F/M 구간 경계
3. scaler와 PCA 가중치
4. 등급 컷과 세그먼트 규칙
5. 입력 데이터 해시와 실행 시각

## 5. 검증 원칙

같은 기간의 F/M으로 등급을 만들고 같은 기간의 매출·재방문을 비교하는 것은 독립
검증이 아니라 프로파일 확인이다. 검증은 다음처럼 out-of-time으로 수행한다.

1. 과거 기간으로 RFM과 등급 생성
2. 이후 30/60/90일 매출·다른 날 재구매·이탈을 타깃으로 설정
3. 등급별 신뢰구간, 효과크기, lift와 calibration 확인
4. 컷·가중치·90일 기준의 민감도와 드리프트 점검

현재 프로젝트는 1개년 데이터의 탐색 분석이므로 이 검증을 다음 단계로 명시한다.

## 6. KMeans의 위치

KMeans는 보조 탐색이다. 현재 실루엣 점수는 `k=2`가 가장 높아 탐색 그림도 k=2를
사용한다. 최종 5개 등급의 수와 타당성을 정하는 근거로 사용하지 않는다.

## 7. 장기 미방문 기준

`Recency > 90일`은 운영 예시이지 자연적으로 발견된 정답이 아니다. 노트북에서
60/90/120/150일별 대상 규모를 함께 확인하고 실제 캠페인 비용·구매 주기·검정력에
따라 기준을 선택한다.
