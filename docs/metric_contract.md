# 분석 지표 계약

노트북, Tableau, Notion에서 같은 이름을 같은 의미로 사용하기 위한 기준이다.

## 데이터 그레인

| 데이터 | 그레인 | 기준 키 |
|---|---|---|
| `orders_master` | 상품라인 | 원본 행 |
| 고객 주문 | 고객 × 거래ID | `(고객ID, 거래ID)` |
| 고객 | 고객 | `고객ID` |
| 월 코호트 | 고객×관측 첫 구매월×경과월 | `고객ID`, `first_month`, `month_diff` |

## 금액

| 이름 | 정의 | 배송비 |
|---|---|---|
| 상품 총액 | `평균금액 × 수량` | 제외 |
| 할인 후 금액 | 상품 총액에 제공된 쿠폰 할인율 적용 | 제외 |
| 상품 매출·Monetary | 할인 후 금액에 GST 적용한 `세후금액` 합계 | 제외 |
| 고객 결제액 | 상품 매출 + 고객 주문당 배송비 1회 | 포함 |

- 대시보드와 RFM의 기본 매출은 **할인 후·세금 포함·배송비 제외 상품 매출**이다.
- 원자료 52,924행에서 거래ID는 전역으로 25,061개, `(고객ID, 거래ID)`는 26,631개다. 1,319개 ID가 여러 고객에게 재사용된다. 같은 고객 주문 안에서는 날짜·배송료가 각각 하나이므로 고객 주문을 분석용 주문 단위로 사용한다. 원자료만으로 고객 간 공동 결제 여부는 판정할 수 없다.
- 배송비는 같은 고객 주문의 상품라인에 반복된 원본 값을 `(고객ID, 거래ID)`별 `MAX(배송료)`로 한 번만 반영한다. 총 배송비는 $238,987.60이다. 거래ID만 쓴 이전 방식은 $220,522.14였다.
- 환불·원가 데이터가 없어 `순매출`, `이익`, `ROI`라는 용어를 사용하지 않는다.
- 통화 표시는 전 산출물에서 `$`로 통일한다.

## 고객 행동

| 이름 | 정의 | 주의 |
|---|---|---|
| 주문수 | 전역 집계는 `COUNT(DISTINCT 고객ID, 거래ID)`; 고객별 집계는 `COUNT(DISTINCT 거래ID)` | MySQL 다중 컬럼 DISTINCT. 상품라인 수와 다름 |
| 구매일수 | `COUNT(DISTINCT DATE(거래날짜))` | 같은 날 여러 거래는 1일 |
| 최대 구매 간격 | 서로 다른 구매일을 시간순으로 정렬한 연속 구매일 간격의 최댓값 | 구매일이 하루뿐이면 원시값은 `NULL`; 분류 시 0으로 처리 |
| 연간 재방문 | 구매일수 > 1 | RFM Frequency와 연관됨 |
| 관측기간 첫 구매 | 2019년 데이터에서 가장 이른 구매 | 실제 생애 첫 구매·신규 획득 아님 |
| 월 리텐션 | 관측 첫 구매월 고객 중 +N개월 구매 고객 비율 | 실제 신규 코호트 아님 |
| 장기 미방문 | 기준일 대비 Recency > 운영 시나리오 일수 | 60/90/120/150일 민감도 병기 |

## 해석 원칙

- RFM은 기준일까지 관측한 최근성·고객 주문 빈도·누적 상품매출의 프로파일이다. 동일 기간 등급별 매출·Frequency·재방문 차이는 등급 정의의 영향을 포함하므로 미래 성과 `검증`으로 부르지 않는다.
- 한 해의 월별 차이는 `달력 월 집중`으로 표현하고 다년도 반복이 확인되기 전에는 계절성으로 확정하지 않는다.
- 캠페인 ID, 고객별 노출, 마진이 없으므로 마케팅 분석은 연관성만 기술한다.
- `효과`, `최적`, `전환`은 무작위 실험 또는 후속 기간 검증이 있을 때만 사용한다.
