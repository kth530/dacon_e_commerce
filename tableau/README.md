# Tableau CSV 추출

최종 [02 데이터 준비](../notebooks/02_data_preparation.ipynb)의 `pipeline` 셀과 [03 데이터 개요](../notebooks/03_data_overview.ipynb)의 산점도 좌표 셀, [04 가설 검증](../notebooks/04_eda_validation.ipynb)의 구매 간격 셀을 사용한다. 노트북의 핵심 로직을 복사해 유지하지 않는다. `data/`의 원천 CSV 5개만 있으면 실행되며 MySQL은 선택 대조용이다. 재사용할 수 있는 영속 분석 마트나 캐시가 없어 원천 전처리를 한 번 실행한다.

## 실행과 입력

프로젝트 루트에서 `requirements.txt`의 Python 패키지를 설치하고 다음을 실행한다. 02→03→04의 필요한 셀을 한 프로세스에서 순서대로 실행하고, 3개 CSV의 행·키·금액·등급·리텐션을 검사한 다음 기존 파일을 교체한다. 검증에 실패하면 CSV를 교체하지 않는다. `scripts/run_pipeline.py --with-tableau`도 동작하지만 노트북 전체 실행 후 추출을 다시 수행하므로 CSV만 만들 때는 아래 명령을 사용한다.

```bash
python tableau/export_csv.py
python tableau/export_csv.py --verify-mysql  # 선택: .env의 기존 DB를 읽기 전용으로 대조
python tableau/export_csv.py --output-dir /tmp/tableau-csv-check  # 선택: 별도 폴더에 먼저 생성
```

입력은 `data/Onlinesales_info.csv`, `Customer_info.csv`, `Discount_info.csv`, `Marketing_info.csv`, `Tax_info.csv`다. `--verify-mysql`은 `.env`의 `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`를 사용해 `rfm_result`의 고객별 등급·세그먼트·RFM 값과 `orders_master`의 고객 주문별 라인 수·날짜·상품매출·배송비를 Python 결과와 비교한다. 일치하더라도 DB에 원천 파일 및 코드 버전 정보가 없어 적재 버전 자체는 증명할 수 없다. CSV 생성에는 DB 값을 사용하지 않는다.

출력 시 `pipeline_metadata.json`에 원천 파일·실행된 분석 셀의 SHA-256, 검증 결과, 선택 DB 대조 결과를 기록한다. CSV와 메타데이터는 Git 추적 대상이 아니다. 교체 전 자료가 필요하면 별도로 보관한다.

## CSV 계약

단일 페이지 시안에 필요한 고객·주문·코호트 CSV 세 개를 생성한다. 월별 매출·마케팅을 담은 `v_tableau_monthly.csv`는 이 화면에서 쓰지 않으므로 생성하지 않는다. 등급×세그먼트 고객 수와 Recency·Frequency·Monetary 비교는 고객 CSV에서 바로 집계하므로 `segment_profile.csv`도 만들지 않는다.

| 파일 | 행 단위와 행 수 | 컬럼 | 사용 목적 |
|---|---|---|---|
| `v_tableau_customer.csv` | 고객 1명당 1행, 1,468행 | 기존 `고객ID`, `등급`, `세그먼트`, `R`, `F`, `M`, `RFM_score`, `Recency`, `거래건수`, `총지출`, `성별`, `고객지역`, `가입기간`, `구매일수`, `재방문여부`, `첫구매월`, `R_scale`, `F_scale`, `marker_size`; 추가 `다음달관찰가능`, `첫구매월+1개월복귀`, `장기미방문_90일예시`, `최대구매간격_일`, `공백상태_90일예시` | 등급별 고객 수·비중과 재방문, R·F 산점도, 등급 내부 세그먼트·구매 상태, CRM 검증 후보 |
| `v_tableau_orders.csv` | 상품라인 1개당 1행, 52,924행 | `고객ID`, `거래ID`, `고객주문키`, `거래날짜`, `월`, `제품카테고리`, `제품ID`, `수량`, `세후금액`, `쿠폰상태`, `성별`, `고객지역`, `가입기간`, `등급`, `세그먼트`, `R`, `F`, `M` | 등급별 상품매출·비중과 기존 주문 워크시트 |
| `cohort_retention.csv` | 등급×**2019년 관측 첫 구매월**×경과월 1행, 720행 | 기존 `등급`, `코호트월`, `경과월`, `고객수`, `코호트크기`, `리텐션율`; 추가 `관찰가능` | H1의 전체 코호트 리텐션과 정확한 분자·분모 |

기존 컬럼명·등급명·세그먼트명과 산점도 좌표·크기는 유지했다. 수치형 `R`, `F`, `M`, `R_scale`, `F_scale`, `marker_size`, `고객수`, `코호트크기`, `리텐션율`도 숫자로 출력한다. 신규 고객 필드는 0/1 관찰 여부 또는 구매 공백 예시이며, 실제 캠페인 성과가 아니다. `첫구매월` 및 `코호트월`은 생애 첫 구매월이 아니라 **2019년 데이터에서 처음 관측된 구매월**이다.

`고객주문키`는 `고객ID|거래ID`이다. `거래ID`는 고객 사이에 중복될 수 있어 주문 수에는 `COUNTD([고객주문키])`를 사용한다. `세후금액`과 `총지출`은 할인 후·GST 포함·배송비 제외 상품매출이다. 등급별 상품매출은 주문 CSV의 `SUM([세후금액])` 또는 고객 CSV의 `SUM([총지출])`로 계산하며, 두 합계는 같다. 서로 다른 grain의 두 파일을 직접 조인해 매출이나 고객 수를 합산하면 중복된다.

### 코호트의 0과 미관측

- `관찰가능=1`: `코호트월+경과월≤12`. 구매가 없는 월도 `고객수=0`, `코호트크기>0`, `리텐션율=0`으로 남긴다.
- `관찰가능=0`: 2019년 말 이후라 확인할 수 없는 월. `고객수`, `코호트크기`, `리텐션율`을 빈 값으로 둔다. 0%로 표시하지 않는다.
- 같은 등급·코호트의 관찰 가능한 경과월 분모는 코호트의 전체 고객 수다. 특정 경과월의 전체 또는 선택 등급 리텐션은 `SUM([고객수]) / SUM([코호트크기])`로 구한다. 기존 `리텐션율`은 개별 행의 0~100 값이며, 등급별 비율을 합산하는 용도가 아니다.
- +1개월 관찰 가능 고객 1,362명 중 130명이 해당 월에 다시 구매했다(9.54%). 12월 첫 관측 고객 106명은 +1개월 분모에 포함되지 않는다.

## 워크북 교체 시 확인할 사항

이번 작업은 `.twbx`를 수정하지 않았다. 고객·주문·코호트 CSV의 기존 필드명은 유지해 색상·범례·산점도 워크시트를 재사용할 수 있다. 기존 워크북의 월별 데이터 원본을 쓰는 워크시트는 이 세 파일만으로 다시 연결할 수 없다. 새 단일 페이지에서 해당 시트를 제외하거나, 과거 월별 CSV를 별도로 보관해 연결해야 한다. 워크북 안의 Hyper 추출과 공개 Tableau 화면은 CSV 교체만으로 갱신되지 않으므로 데이터 원본을 새 파일에 다시 연결하고 추출을 새로 고쳐야 한다.

| 대상 | 필요한 Tableau 작업 |
|---|---|
| `코호트 리텐션` 워크시트 | 현재 `SUM([리텐션율])` 집계를 사용한다. `SUM([고객수]) / SUM([코호트크기])` 계산 필드로 바꾸고 퍼센트 형식을 적용한다. `관찰가능=1` 필터를 걸어 미관측 월을 0으로 그리지 않는다. |
| 등급별 주문 수가 있는 워크시트 | `COUNTD([거래ID])`를 쓰는 곳은 `COUNTD([고객주문키])`로 바꾼다. |
| 새 단일 대시보드의 등급 선택 | 기존 `등급 분포 선택 → 행동 세그먼트 필터`, `등급별 재방문율 선택 필터`, `하이라이트1` 액션은 옛 대시보드의 시트 참조를 사용한다. 새 1600×900 시안에서는 등급 버튼이 H3의 고객 산점도와 등급 내부 비교만 필터링하도록 다시 지정한다. 상단 KPI와 H1·H2는 전체 기준으로 고정한다. |
| 코호트와 다른 데이터 원본 | 코호트는 별도 CSV 원본이다. 이 시안에서는 H1에 등급 필터 액션을 연결하지 않는다. 전체 리텐션은 등급 비율의 합이나 평균이 아니라 관찰 가능한 분자·분모 합으로 계산한다. |
| 기존 월별·카테고리·지역 시트 | 새 단일 페이지에 배치하지 않는다. 월별 데이터 원본을 쓰는 과거 워크시트에는 별도 보관한 월별 CSV가 필요하다. 카테고리·지역에 필요한 주문 필드는 유지한다. |

H1은 고객 CSV의 `재방문여부`로 연간 다른 날 재방문율을, 코호트 CSV로 관측 첫 구매월 리텐션을 표시한다. H2는 고객 CSV의 고객 수·재방문과 주문 CSV의 상품매출을 등급별로 비교한다. H3는 고객 CSV의 `R_scale`, `F_scale`, `marker_size`, `등급`, `세그먼트`로 기존 산점도를 유지하고, `Recency`, `거래건수`, `총지출`, 구매 공백 필드로 같은 등급 안의 차이를 본다. 04 노트북의 Bronze 재참여, Silver·Gold 접촉 시점, Platinum 메시지 개인화, Diamond·Platinum 혜택 방식 비교는 **후속 검증 후보**로 설명한다. 무작위 배정·실제 캠페인·성과 데이터는 이 CSV에 없다.
